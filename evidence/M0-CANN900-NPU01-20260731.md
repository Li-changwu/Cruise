# M0 CANN 9.0.0 NPU0-1 Installation Checkpoint

Date: 2026-07-31 (Asia/Shanghai)

Status: accepted as an installation, compatibility, and asset-provisioning
checkpoint. At capture time this did not yet close M0 or promote the CANN 9.0.0
profile. The later lifecycle gate is recorded separately.

## Target and Scope

The run used SSH target `NPU0-1`, Conda environment `vllm-hust-dev`, and
physical NPU 0. The target exposes two healthy Ascend 910B2 devices. NPU 0 had
no active compute process before qualification. The source checkout and wheel
build lived on `/workspace`, a separate 5.9 TiB volume, rather than the root
disk. At the start of qualification:

- root filesystem usage was 383 GiB of 893 GiB (45%);
- `/workspace` usage was 353 GiB of 5.9 TiB (6%);
- `/dev/shm` had 992 GiB free;
- physical NPU 0 reported health `OK` and no running process.

The container hostname is not used as machine identity because it is inherited
from an image template. The SSH target, selected physical device, software
profile, and captured hardware state define this checkpoint.

- all three required custom OPP vendor trees.

Cruise materialized the 342 immutable AIR runtime-weight files once from that
existing frozen model into the dedicated data-volume store
`/workspace/cruise-assets/runtime-weights/2ec95b...6761`. The published files
total 15,231,237,408 bytes and the manifest SHA256 is
`2ec95bf8e78cfaf091782b3c531b19b9cced35dcfab0e418c756e25abe456761`.
A second identical provisioning command deep-hashed all files and returned
`reused=true`; it created no second weight directory and left no staging path.
The complete marked store occupies 15,231,335,931 bytes including its manifest
and marker.

The runtime configuration now distinguishes immutable AIR weights from
GraphPp-generated external weights. The former may remain on a dedicated data
volume and are never cleanup targets. The latter are created below each
managed `/dev/shm` run and removed on stop. Socket, KV transfer, cache, logs,
and temporary files remain strictly confined to `/dev/shm`.

Cruise now reports a missing required file or external-weight directory as
`missing-runtime-asset`, including the expected path, observed state, and a
remediation that requires the selected profile's content-addressed bundle and
forbids substituting an unqualified model. A non-executable sidecar is reported
as `invalid-runtime-asset-permissions`.
