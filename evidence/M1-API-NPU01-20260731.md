## Semantic Coverage

Both stock vLLM and Cruise passed all eight cases with identical token IDs,
finish reasons, and response shape:

1. non-streaming single request;
2. non-streaming batch request;
3. streaming single request;
4. streaming batch request;
5. EOS on the second token;
6. `max_tokens` with unsupported `min_tokens` fallback;
7. streaming disconnect after device ownership;
8. a successful post-disconnect probe.

The final comparison has `baseline_passed=true`, `cruise_passed=true`,
`exact_api_semantics=true`, `same_case_set=true`, and `mismatches={}`.
Server return codes and logger return codes were zero. The disconnect case
closed exactly at the requested boundary, and the post-disconnect request
succeeded without a restart.
